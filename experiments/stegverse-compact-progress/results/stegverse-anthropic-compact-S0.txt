## 2. Stipulated Definitions (Input Layer)

The following are **stipulations**, not derived claims. They define the abstract evaluator for this experiment.

| Symbol | Kind | Meaning |
|--------|------|---------|
| `C` | Type | The type of candidate transitions |
| `GBP` | Predicate `C → Prop` | "Good-by-policy" condition |
| `BD` | Predicate `C → Prop` | "Boundary" condition |
| `OC` | Predicate `C → Prop` | "Other-condition" condition |
| `ALLOW` | Predicate `C → Prop` | The evaluator's admit decision |

**Evaluator stipulation (S-DEF):**
> The abstract GCAT/BCAT evaluator returns ALLOW on candidate `c` if and only if `GBP(c)`, `BD(c)`, and `OC(c)` all hold.

This is an **axiomatic stipulation** for this experiment. It does not assert that any deployed system conforms.

## 3. Claim Boundary

### 3.1 What is in scope for this experiment

- **Claim target:** A necessary-and-sufficient logical characterization of `ALLOW` in terms of `GBP`, `BD`, `OC`, under S-DEF.
- **Lean 4 artifact target:** A candidate formalization of the logical core (to be produced in a later stage).

### 3.2 What is explicitly out of scope

| Out-of-scope item | Reason |
|---|---|
| Conformance of any deployed GCAT/BCAT system | Not asserted; governance prohibition |
| Soundness of any compiled Lean 4 artifact | Implementation validity not claimed |
| Semantic content proven by any artifact hash | Hash proves identity only, per governance |
| Properties of `GBP`, `BD`, `OC` beyond their role in S-DEF | Not stipulated here |

### 3.3 Claim tier structure (for subsequent stages)

| Tier | Label | Content |
|------|-------|---------|
| T0 | Stipulation | S-DEF as above |
| T1 | Generated claim | Necessary-and-sufficient statement derived from S-DEF |
| T2 | Lean 4 candidate | Formalization of T1; validity not asserted |
| T3 | Verified claim | Would require external proof-checker confirmation; not reached in this experiment |
