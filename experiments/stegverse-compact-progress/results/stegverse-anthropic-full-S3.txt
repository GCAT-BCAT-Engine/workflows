### 2. Proof Strategy Selection

#### 2.1 Available Strategies

Three candidate strategies are identified and evaluated:

| Strategy ID | Name | Description | Applicability |
|-------------|------|-------------|---------------|
| PS-A | Definitional unfolding | Prove both directions by `rfl` or `exact id` after unfolding DEF-3 | Applicable; exploits the fact that ALLOW is a `def`, not an inductive type |
| PS-B | Iff introduction with explicit constructors | Use `Iff.intro` to provide forward and backward functions explicitly | Applicable; maximally explicit; preferred for decomposition clarity |
| PS-C | `tauto` / decision procedure | Dispatch the entire biconditional to a propositional tactic | Applicable but opaque; obscures lemma structure |

#### 2.2 Selected Strategy

**Primary strategy: PS-B (Iff introduction with explicit constructors).**

Rationale:
- Maximally transparent: each lemma corresponds to exactly one proof obligation.
- Compatible with the lemma decomposition goal of this stage.
- Constructive throughout (ASM-1); no appeal to classical logic.
- Supports clean Lean 4 candidate generation in S4.

**Secondary fallback: PS-A (Definitional unfolding).**

Rationale: Because ALLOW is defined by `def` in Lean 4 (not `inductive`), both directions reduce to `id` after unfolding. PS-B will be implemented to use `fun h => h` and `fun h => h` respectively, which is the explicit form of definitional equality at `Prop`. PS-A is thus the degenerate case of PS-B.

PS-C is set aside; it would be valid but provides no decomposition structure.
