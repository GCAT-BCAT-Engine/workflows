S3: Proof strategy and lemma decomposition.

**Stipulation**

For arbitrary predicates
`GBP BD OC ALLOW : Transition → Prop`, assume:

\[
hEval:\forall t,\ ALLOW(t)\leftrightarrow GBP(t)\land BD(t)\land OC(t).
\]

No decidability, independence, or predicate semantics are assumed.

**Generated claims**

For every transition `t`:

1. **Necessity**
   \[
   ALLOW(t)\rightarrow GBP(t)\land BD(t)\land OC(t).
   \]

2. **Sufficiency**
   \[
   GBP(t)\land BD(t)\land OC(t)\rightarrow ALLOW(t).
   \]

3. **Necessary-and-sufficient characterization**
   \[
   ALLOW(t)\leftrightarrow GBP(t)\land BD(t)\land OC(t).
   \]

**Proof strategy**

- Derive necessity using the forward implication `(hEval t).mp`.
- Derive sufficiency using the reverse implication `(hEval t).mpr`.
- Construct the characterization from those two directional lemmas.
- The proof is purely propositional; no case analysis or classical reasoning is required.

**Lean 4 logical-core candidate**

```lean
universe u

variable {Transition : Type u}
variable {GBP BD OC ALLOW : Transition → Prop}

theorem allow_necessity
    (hEval : ∀ t, ALLOW t ↔ GBP t ∧ BD t ∧ OC t)
    (t : Transition)
    (hAllow : ALLOW t) :
    GBP t ∧ BD t ∧ OC t :=
  (hEval t).mp hAllow

theorem allow_sufficiency
    (hEval : ∀ t, ALLOW t ↔ GBP t ∧ BD t ∧ OC t)
    (t : Transition)
    (hConditions : GBP t ∧ BD t ∧ OC t) :
    ALLOW t :=
  (hEval t).mpr hConditions

theorem allow_admissible_iff
    (hEval : ∀ t, ALLOW t ↔ GBP t ∧ BD t ∧ OC t)
    (t : Transition) :
    ALLOW t ↔ GBP t ∧ BD t ∧ OC t := by
  constructor
  · exact allow_necessity hEval t
  · exact allow_sufficiency hEval t
```

**Verified claims**

- The theorem formulation and abstract evaluator equivalence are admitted from prior-stage artifacts.
- No Lean compilation or proof-kernel verification is asserted at this stage.

**Claim boundary and unresolved evidence**

These claims characterize only the stipulated abstract evaluator. No claim is made that any deployed or concrete GCAT/BCAT evaluator uses these predicates, satisfies `hEval`, or conforms to this Lean candidate. Implementation binding, compilation, and deployment conformance remain unresolved.
